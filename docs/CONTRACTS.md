# Smart Contracts

Solidity contracts for the Rainfall-Based Parametric Crop Insurance DApp. Prototype only: test tokens, no real funds, not an insurance product, not audited.

## Contracts

| Contract | Purpose |
|---|---|
| `contracts/CropInsurance.sol` | Stores the fixed policy catalogue, enrols farmers, accepts the final rainfall report, checks eligibility and pays the test-token payout. |
| `contracts/TestToken.sol` | Test-only ERC-20 (`RTT`) used for payouts. Only the deployer can mint. |
| `contracts/RainfallReportReceiver.sol` | CRE consumer contract. Accepts reports only from the configured forwarder, decodes the payload and calls `CropInsurance.recordRainfall`. |
| `contracts/interfaces/ICropInsurance.sol` | Interface shared with the CRE workflow and frontend. |
| `script/PolicyCatalogue.sol` | The 13 catalogue options passed to `CropInsurance` at deployment. Also used by the tests. |
| `contracts/cre/IReceiver.sol`, `contracts/cre/ReceiverTemplate.sol` | Official Chainlink CRE receiver interface and template, taken from the CRE "Building Consumer Contracts" guide. |

Flow: farmer calls `enroll` → coverage runs → CRE workflow → `KeystoneForwarder` (verifies DON signatures) → `RainfallReportReceiver.onReport` → `CropInsurance.recordRainfall` → farmer calls `claim`.

## Interface agreement

Units:

- Rainfall and trigger: whole millimetres (`uint256`). The workflow converts the Open-Meteo total to whole millimetres using the rounding rule the team agrees and documents.
- Latitude and longitude: degrees × 1,000,000 (`int32`), e.g. `13.1367` → `13136700`.
- `startTime` and `endTime`: Unix seconds, UTC. The window covers `startTime` up to, but not including, `endTime`.
- `duration`: seconds. All durations are whole hours.
- Start times must be on a full UTC hour. In India time that is always :30 (00:00 UTC = 05:30 IST).

Example: Option 6 starting 05 Dec 2026 00:00 UTC has `startTime = 1796428800` and `endTime = 1801612800` (03 Feb 2027 00:00 UTC).

Catalogue option (`getOption`): `thresholdMm`, `duration`, `payoutAmount`.

Policy fields (`getPolicy`): `owner`, `optionId`, `latitudeE6`, `longitudeE6`, `startTime`, `endTime`, `thresholdMm`, `payoutAmount`, `reported`, `rainfallMm`, `claimed`.

Functions:

| Function | Caller |
|---|---|
| `enroll(optionId, latitudeE6, longitudeE6, startTime)` | Farmer |
| `claim(policyId)` | Policy owner |
| `optionCount()`, `getOption(optionId)` | Anyone (read the catalogue) |
| `getPolicy(policyId)`, `isEligible(policyId)`, `nextPolicyId()` | Anyone (read) |
| `recordRainfall(policyId, startTime, endTime, rainfallMm)` | Report receiver only |

Events:

- `PolicyCreated(policyId, owner, optionId)`
- `RainfallReportAccepted(policyId, rainfallMm)`
- `ClaimPaid(policyId, owner, amount)`

Report payload (ABI-encoded, written by the CRE workflow):

```
(uint8 version, uint256 policyId, uint64 startTime, uint64 endTime, uint256 rainfallMm)
```

Example values:

```json
{"version":1,"policyId":3,"startTime":1796428800,"endTime":1801612800,"rainfallMm":82}
```

ABIs are generated by `forge build` in `out/<Contract>.sol/<Contract>.json`. Deployed addresses are written to `deployments/<chainId>.json`.

## Policy catalogue

Fixed at deployment in `script/PolicyCatalogue.sol`. There is no function to add, edit or remove options.

Rule: a typical field crop needs about 5 mm of water per day. Each trigger is the rainfall that meets only a set share of that need. Trigger = mm/day × days; payout = RTT/day × days.

| Level | Rainfall | Share of need | Payout |
|---|---|---|---|
| Severe | 1 mm/day | ~20% | 3 RTT/day |
| Moderate | 2 mm/day | ~40% | 2 RTT/day |
| Mild | 3 mm/day | ~60% | 1 RTT/day |

| ID | Level | Duration | Trigger | Payout |
|---|---|---|---|---|
| 0 | Demo | 2 hours | 1 mm | 10 RTT |
| 1–4 | Severe | 30 / 60 / 90 / 120 days | 30 / 60 / 90 / 120 mm | 90 / 180 / 270 / 360 RTT |
| 5–8 | Moderate | 30 / 60 / 90 / 120 days | 60 / 120 / 180 / 240 mm | 60 / 120 / 180 / 240 RTT |
| 9–12 | Mild | 30 / 60 / 90 / 120 days | 90 / 180 / 270 / 360 mm | 30 / 60 / 90 / 120 RTT |

The level names are not stored on-chain. The frontend derives them from the option ID (0 = Demo, 1–4 = Severe, 5–8 = Moderate, 9–12 = Mild).

## Business rules

| Rule | Behaviour |
|---|---|
| Catalogue | Set once in the constructor; each option needs trigger > 0, payout > 0 and a duration of whole hours. No edit function. |
| Enrolment | Option must exist, latitude within ±90°, longitude within ±180°, start in the future and on a full UTC hour. End = start + option duration (calculated by the contract). The option's trigger and payout are copied into the policy. |
| Report source | Only the receiver contract can call `recordRainfall`. Only the configured forwarder can call `onReport`. |
| Report version | Only version `1` is accepted. |
| Coverage window | The report's start and end must match the policy exactly, and `endTime` must have passed. |
| Duplicate report | One final report per policy; a second report reverts. |
| Eligibility | Rainfall strictly below the trigger. Equal to the trigger does not qualify. |
| Claim | Policy owner only, after an accepted report, once only. |
| Funding | Claim reverts with `InsufficientPayoutBalance` if the contract holds too few tokens. |
| Missing data | No report means no claim. Missing data is never treated as zero rainfall. |

## Security

- Custom errors for every failed check.
- Checks-effects-interactions in `claim`: the policy is marked `claimed` before the transfer.
- OpenZeppelin `SafeERC20` for transfers, `ERC20` for the token and `Ownable` for admin functions.
- Tests cover access control and every state transition (see below). The contracts are tested, not audited.
- Development keys only. Never commit `.env`.

Admin controls (deployer account):

- `CropInsurance.setReportReceiver(address)`: sets the receiver contract.
- `RainfallReportReceiver.setForwarderAddress(address)`: switches between the MockForwarder (simulation), KeystoneForwarder (deployment) or local fallback reporter.
- `RainfallReportReceiver.setExpectedWorkflowId(bytes32)` and `setExpectedAuthor(address)`: restrict reports to the team's workflow once it is deployed. Do not set these during `cre workflow simulate`; the MockForwarder does not send workflow metadata.

## AI recommendation and contract separation

The AI recommends a catalogue option and a start date. It is advisory and runs off-chain. The contracts have no function, field or parameter that accepts an AI output. Farmers can only choose from the fixed catalogue, and a claim is paid only when:

1. a verified rainfall report has been accepted through the receiver,
2. the report matches the policy's coverage window,
3. the reported rainfall is strictly below the trigger, and
4. the policy has not already been claimed.

`test_RevertWhen_ClaimWithoutAcceptedReport` and `test_RevertWhen_ReportFromUnauthorizedCaller` show that nothing other than an accepted report can make a policy payable.

## Setup

Requires [Foundry](https://book.getfoundry.sh/) (tested with forge 1.5.1, solc 0.8.24). Dependencies: forge-std v1.9.4 and OpenZeppelin Contracts v5.1.0.

First-time setup, before the repository's first push:

```bash
git init
forge install foundry-rs/forge-std@v1.9.4 OpenZeppelin/openzeppelin-contracts@v5.1.0
```

After cloning the team repository:

```bash
git submodule update --init --recursive
```

Build and test:

```bash
forge build
forge test -vv
```

## Local deployment (Anvil)

```bash
anvil
cp .env.example .env    # set PRIVATE_KEY to an Anvil account and FORWARDER_ADDRESS
source .env
forge script script/Deploy.s.sol --rpc-url $RPC_URL --broadcast
```

The script deploys `TestToken`, `CropInsurance` (with the 13-option catalogue) and `RainfallReportReceiver`, links the receiver, mints 1,000,000 RTT to the insurance contract and writes the addresses to `deployments/<chainId>.json`.

`FORWARDER_ADDRESS` depends on the environment:

| Environment | Value |
|---|---|
| CRE simulation | MockKeystoneForwarder for the chosen network (see the CRE Forwarder Directory) |
| CRE deployment | KeystoneForwarder for the chosen network |
| Local fallback | A local reporter account. This must be labelled as a fallback, not as decentralized oracle execution. |

If the CRE simulation does not support Anvil, deploy with the same script to the supported test network by changing `RPC_URL`.

## Tests

`forge test` runs 34 tests:

| Area | Tests |
|---|---|
| Catalogue | 13 options; demo option values; options 1–12 follow the rule; empty catalogue, invalid terms and out-of-range option ID rejected. |
| Enrolment | Policy stored with copied terms and calculated end; `PolicyCreated` includes the option ID; demo option ends 2 hours later; unknown option, past/current start, start not on a full hour, invalid location and unknown policy rejected. |
| Reports | Unauthorized caller rejected (insurance and receiver); report before coverage ends, mismatched window, duplicate report, unsupported version and malformed payload rejected; workflow ID check accepts the expected workflow and rejects others; ERC-165 support. |
| Eligibility | Below trigger pays; equal to and above trigger are not eligible; full demo-option cycle. |
| Claims | Duplicate claim rejected with no second transfer; insufficient balance fails safely; non-owner rejected; no claim without an accepted report; only the owner can set the receiver. |

## Limitations

- Prototype with test tokens only. No premiums. Catalogue values follow a clear rule but are not actuarially priced.
- One final report per policy; there is no correction or dispute process.
- The report payload has no chain identifier, so cross-chain replay protection is out of scope for the single-chain demo.
- Correctness depends on the weather data and on how the workflow computes the rainfall total.
- Not audited.
